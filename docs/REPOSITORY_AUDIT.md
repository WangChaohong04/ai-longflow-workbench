# 仓库文件保留与发布审计

本文区分开源交付必需文件、本地运行数据和真正废弃文件。不按文件数量或测试名称判断是否冗余。

## 保留并发布

| 路径 | 用途 |
| --- | --- |
| `longflow/` | API、任务编排、权限、知识检索、核验和工作台源码 |
| `config/` | 无凭证的默认配置与领域/场景定义 |
| `knowledge/` | 离线知识样例 |
| `plugins/` | 可信本地插件及 GEO 样例数据 |
| `plugins/geo/data/sample.geojson` | 新用户克隆后运行 GEO 的必要样例，不是运行数据库 |
| `tests/` | 单元、契约、集成、回归用例；真实服务测试显式 opt-in |
| `tools/` | 可选配置引导、前端检查和检索诊断入口 |
| `README.md`、`SPEC.md`、`docs/` | 入门、实现流程、技术边界和验收说明 |
| `.env.example` | 仅变量名和占位符，程序不会自动加载 `.env` |
| `requirements.txt`、`LICENSE`、`.github/workflows/ci.yml` | 依赖、许可证和自动检查 |

## 本地保留但不上传

- 根目录 `data/`：用户运行数据库、WAL/SHM、服务日志。不要为清理仓库而删除用户任务数据。
- `.lfwork/`：测试及本地验收临时工作目录。
- `.agent-teams/`：本机协作会话记录，不属于项目源码。
- `.env`、`.env.*`（除 `.env.example`）：本机配置和可能存在的凭证。
- Python 缓存、虚拟环境、测试缓存、Node 依赖和浏览器测试产物。

`.gitignore` 将原来的 `data/` 改为 `/data/`：仅排除根目录运行数据，避免误排除插件目录内的 GEO 样例。数据库和日志扩展名仍全局排除。

## 已确认废弃文件

- `tests/test_bing_provider.py`：文件只有模块级永久 `pytest.skip`，注释明确已弃用。删除不减少任何实际执行的测试。不能据此声称项目支持 Bing 搜索。

- `tools/smoke_bing.py`：只退出并提示使用百度脚本，没有可执行的 Bing 诊断逻辑，删除该废弃入口。

## 不宜盲目删除的测试

`test_eval_cases.py` 将 YAML 评测用例接入 pytest；`test_eval_e2e.py` 对关键契约作独立交叉验证。二者虽然流程相近，但断言入口不同，不应仅因名称相似删除。

真实模型、网页、浏览器和可选依赖测试因环境条件跳过，不等同废弃测试；应保留并说明运行条件。

## 发布前检查原则

1. 审查 Git 暂存清单而不是直接上传整个目录。
2. 确认运行数据库、日志、密钥和会话文件未进入暂存区。
3. 从待发布文件生成干净副本进行验证，防止依赖被忽略的本机文件。
4. 区分 Python 回归、JavaScript 静态检查、HTTP 入口检查和真实浏览器 DOM 验证；任何一项不能冒充另一项。
5. GitHub Actions 配置存在不代表远程运行已通过，远程状态需单独核对。
